# UrbanHeatOpt 竞赛版模型假设与边界

## 1. 状态声明

本文记录比赛版 P0 的明确简化、原模型兼容边界和禁止推断事项。它不是武汉真实参数表，也不表示原始 UrbanHeatOpt 已经具备比赛目标中的候选站点生成、独立设备调度、碳排或道路管网能力。

当前统一新 Core 已支持三种供热模式、独立设备、成本—碳排、储热、三档管径、Pareto 和 QA；draft.2 校验器、CLI 及光谷 v0.2 自动适配已接通。V0 可生成确定性负荷中心站和欧氏 MST，但真实道路网络、正式温度性能、正式参数与完整供暖季仍是 V1.0 发布阻塞。旧 v1/v2.1 只保留显式 legacy 回归，正式入口不静默回退。

## 2. P0 合成闭环的目标假设

| 主题 | P0 规则 | 结果解释边界 |
|---|---|---|
| 数据 | 4 栋、24 小时等小型合成输入，全部标记 `synthetic_test` | 不代表光谷、武汉或任何真实建筑 |
| 负荷 | 输入是已经完成面积缩放的最终热功率，浮点 kW | 不再次按面积或天气修正 |
| 时间 | Asia/Shanghai、1h、`timestamp → hour=1...N` | 24/48 小时只用于测试，不是供暖季或年度结果 |
| DHW | 读取 `dhw_included`；适配器固定不额外添加 | `false` 的 smoke 结果标记 `space_heating_only`；正式全服务案例必须已含 DHW |
| 设备 | 一个候选能源站可分别关联中央空气源热泵和中央燃气锅炉；另有建筑本地空气源热泵 | 三种角色使用不同 `technology_id`；禁止合并成 `fixed_heat_source` |
| 性能 | 首版使用技术表中的固定 COP/固定效率 | `Q_e=Q_heat/COP`；`Q_gas,LHV=Q_heat/efficiency`；不从室外温度动态修正 |
| 价格与时间权重 | 电价、LHV 气价是逐时绝对价格；`time_weight_h_per_year` 对同一小时的全部技术公共 | 不接受 multiplier/index；短时 smoke 可年化但仍不代表武汉正式年度结果 |
| 经济目标 | 设备/管网按附件口径简单年化；接入年化与 HNS 罚值为项目批准扩展，并把真实成本与罚项分开 | 不使用 CRF、折现、更换、残值；不含未获批准的站点固定 CAPEX |
| 余热 | P0 smoke 不启用余热，也不创建伪空余热曲线 | 后续真实资源需要锚点和可用量 |
| 储热 | P0 smoke 不启用储热，结果文件保留正式空表头 | 不代表储热模型已经通过验证 |
| 聚类 | KMeans 固定 `random_seed=202611`、`n_init=10` | 聚类数不得超过有效建筑数 |
| 候选点 | V0 按年度供暖量加权建筑质心生成唯一负荷中心站 | 未贴靠道路或可建设地块，不是优化选址或可施工方案 |
| 候选网络 | V0 在站点和建筑质心之间生成确定性欧氏 MST | 仅为联调基线，不受道路、禁建区或施工条件约束 |
| 峰值容量裕度 | V0 配置为 20%，中央设备合计或逐节点本地热泵均按逐时可用容量校核 | 不是 N-1、不指定锅炉份额，水蓄热不计入裕度 |
| 求解 | 默认 HiGHS、单线程、60 秒时限、固定随机种子；可显式选择 Gurobi | 只有 `optimal` 后才允许加载变量和导出；不可用时不静默回退 |
| 碳排 | 输入契约预留因子，P0 最小闭环暂不做 Pareto | 不得把缺失碳功能称为完成 |

## 3. 标准输入与原模型兼容层

标准输入是唯一主数据，旧文件只由适配器生成：

| 标准语义 | 兼容语义 | 强制处理 |
|---|---|---|
| `timestamp` | `hour` | 稳定映射为严格连续的 `1...N`，保存对照表 |
| `building_id` 长表 | `Building_TS.csv` 建筑列 | 集合和大小写精确相等 |
| `heating_kW` float64 | 宽表数值 | 仍为 kW，不 `/1000`、不 `×1000`、不转 `uint32` |
| `heated_area_m2` | `heated_area` | 一对一改名，不重新缩放负荷 |
| Polygon/MultiPolygon EPSG:4326 | 模型空间对象 | 米制运算前投影至 EPSG:32650 |

原模型储热约束直接使用 `h == 1`、`h - 1` 和 `len(h)`，因此兼容小时编号不能从 0 开始，也不能有缺口、重复或乱序。

模型中间文件 `Heat_Demand.csv`、`Heat_Generation_Units.geojson`、`Heat_Network.geojson`、`Heat_Nodes.geojson`、未来可选 `Heat_WH_Profiles.csv` 和 `Cost_Parameter.json` 都是生成产物，不是比赛标准输入。v2.1 冻结 kW、`hour=1...N`、设备角色、价格和经济接口，但当前旧模型仍通过 `isBoiler` 和合并成本列读取设备；该 legacy 结构不能覆盖 v2.1 的 `technology_id`、COP/效率和载体价格语义。竞赛适配器不得调用会创建案例目录并复制 `default/*.xlsx` 的旧入口；它应在独立工作目录生成所需对象，保持七类源文件只读。

当前 `model.py` 通过行位置读取网络端点，受 GeoJSON 列顺序影响。兼容产物在该问题修复前必须把 `node_from,node_to` 放在前两列，同时竞赛层和后续修复应按列名显式读取；正式契约不把脆弱列顺序当成业务语义。

Legacy 余热曲线实际按 `m3/h` 体积流量解释，再乘供回水温差和 `pCWater=1.16389 kWh/(m3·K)` 得到 kW。如果比赛标准资源以 kW 提供，未来适配器必须显式执行一次 `m3/h = kW / (ΔT × pCWater)` 并记录，不能把 kW 直接塞进旧余热曲线。

## 4. 建筑派生量规则

- `MaxDemand` 只能由目标时间范围内 `heating_kW` 的最大值得到，单位 kW；
- `modelled_period_energy_kWh = sum(heating_kW × 1h)`；
- 只有输入确实覆盖经确认的年度/完整供暖季且外推规则获批时，才能写入有年度含义的 `YearlyDemand`；
- 24/48/168 小时案例不得把时段累计量改名为真实年需求。若旧模型为冒烟测试强制需要该列，只能使用明确标记的 `synthetic_test` 兼容值，并禁止将其作为年度 KPI 导出；
- `number_of_dwellings` 只在经批准的 DHW 计算中使用；不能从面积猜测户数；
- `LocalHeatProdCost` 必须来自技术表或经批准的场景参数；不能沿用来源不明的模板币种；
- `GeneralisedThermCap`、`GeneralisedThermCond` 若当前 P0 计算路径实际不使用，应明确禁用；若旧模型仍强制读取，只能使用带来源的合成测试值，不能包装成真实建筑热参数。

## 5. 能量与未供热定义

竞赛版逐节点逐时平衡目标为：

```text
本地供热 + 管网供热 + 储热放热
- 储热充热 + 未供热量
= 建筑热负荷
```

P0 smoke 不启用储热时简化为：

```text
本地供热 + 管网供热 + 未供热量 = 建筑热负荷
```

竞赛核心的 `unserved_heat_kW` 已进入逐节点逐时平衡，并通过强制容量短缺测试得到非零未供热量；旧 `model.py` 的 `vHNS` 仍未完成同等修复，因此不能用旧模型结果替代竞赛核心的可靠性证据。

## 6. 成本与时间权重

- 币种统一为 CNY；投资、运维、能源价格不得继续使用来源不明的 EUR 模板语义；
- 逐时电价唯一使用 `CNY/kWh_e`，逐时气价唯一使用 `CNY/kWh_LHV`；二者均为绝对价格，不能与隐藏基准价或指数再次相乘；
- 同一小时的 `time_weight_h_per_year` 对中央热泵、中央锅炉和分布式热泵完全相同，不允许设备专属权重；
- 全部逐时权重之和必须与 `economics.expected_weight_sum_h_per_year` 在绝对容差 `1e-9 h/year` 内一致；
- 电费按 `供热量/COP × 电价 × 权重` 计算，燃气费按 `供热量/效率 × LHV气价 × 权重` 计算；可变运维仍按有用热输出计，不能重复包含能源费；
- 设备和管网投资采用附件口径，分别按 `capacity×unit_CAPEX/lifetime`、`built×length×unit_CAPEX/lifetime` 简单年化；接入投资 `connected×connection_CAPEX/lifetime` 是项目批准扩展，一条无向物理管段只计费一次；
- 固定维护唯一按 `capacity × capex_CNY_per_kW × fixed_maintenance_fraction_per_year` 计算；比例范围为 `[0,1]`。附件只列出维护系数字段名，未给可直接采用的数值、设备归属和完整单位，因此不自动填入；
- 可变运维只接收已明确标准化为 `CNY/kWh_th` 的数值；含义不明时阻止正式运行；
- 真实成本由设备、管网、接入年化投资、固定/可变运维、电费和燃气费组成；HNS 惩罚单列并只在最终优化目标中与真实成本相加；
- 当前附件公式不使用规划期、折现率、CRF、更换投资或残值；这些字段仍可追溯，但不得改变当前目标。附件未定义站点固定 CAPEX，当前明确不纳入；
- 体积气价不得进入核心。V0 按用户确认的标准立方米口径和国家缺省 `38.931 MJ/Nm³`，在输入边界将 `3.54 CNY/Nm³` 一次转换为 `0.327348386 CNY/kWh_LHV`；原始量、来源和派生值同时写入假设清单，正式气质和项目气价到位后必须覆盖，核心不会再次换算；
- P0 短时 smoke 只有在显式年度小时权重获批后才可称为合成年度成本，仍不能称为武汉真实年度结果；
- 成本明细必须以 CNY 原精度重算并与目标值对账，不能沿用旧导出中的 kEUR 缩放或四舍五入标签。

## 7. 原代码已知风险和后续修复

| 风险 | 当前证据/影响 | 后续独立任务 |
|---|---|---|
| 建筑辅助空值误删 | 当前读取函数对全表 `dropna()` | 仅检查模型必需字段并建立辅助空值测试 |
| 随机过程未冻结 | KMeans 和原负荷生成器没有统一种子 | P0 不运行随机负荷生成器；KMeans 显式 seed/n_init |
| DHW 重复与 356 天 | 聚类路径无开关且使用 356 | 使用契约布尔值、365 天和开关测试 |
| 无余热崩溃 | 保存路径会对 `None` 写 CSV | 允许无余热场景 |
| 余热只检查第一列 | 曲线核验函数提前返回 | 逐个热源检查并覆盖错误路径 |
| 未供热不入平衡 | `vHNS` 指标可能永远为 0 | 修正约束并建立强制断供测试 |
| 默认 Gurobi | `_config.yaml` 仍为 `gurobi` | 独立切换默认 HiGHS 并检查求解状态 |
| 候选站点缺失 | 原代码没有比赛要求的自动站点生成 | 竞赛层前处理实现 |
| 管网仅直线基线 | Delaunay/MST 不考虑道路和施工约束 | 后续真实空间数据扩展 |
| 管网和储热简化 | 无管网热损失；储热损失固定为 0，缺少充放互斥 | 在 P0 基线中显式披露，后续建立公式测试 |
| 旧模型未使用 v2 经济核心 | 竞赛内存核心已实现三设备与简单年化目标；旧模型仍将可调热源归为 boiler 集合 | 后续适配器和 CLI 必须调用竞赛核心，不得回退到旧合并成本语义 |
| 正式温度 COP 与碳因子缺失 | V0 固定 COP，并使用明确标记的临时电力及直接燃烧 CO₂ 因子 | V1 发布门要求正式性能与碳核算范围 |
| 原导出不安全 | 未确认 optimal 即读取变量，并进行 kEUR 缩放/舍入 | 竞赛 exporter 只在状态通过后按 CNY 原精度输出 |

## 8. 不能由代码组决定的正式参数

以下内容必须由负荷组或项目组提供来源和版本，不能把合成值升级为正式值：

- 正式供暖季、年份类型、闰年处理和 DeST 设定温度；
- 建筑供暖面积口径、DHW 边界、缩放公式和低置信度处理；
- 供回水温度、规划期、折现率和价格基年；其中规划期和折现率在当前简单年化中只追溯；
- 设备 COP/效率、有效范围、容量、投资、固定维护比例、标准化可变运维和寿命；
- 电价、LHV 气价、体积气价配套 LHV/计量基准、碳因子和室外温度时序；
- 道路/可建设空间、禁建规则、资源位置与可利用量。

负荷语义问题见 `questions_for_load_team.md`，项目经济/空间参数见 `questions_for_project_team.md`，真实数据解除条件见 `P0_DEFERRED_REAL_DATA.md`。
