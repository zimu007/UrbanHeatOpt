# 测试版 V0 到正式版 V1.0 的输入契约

## 双轨版本

- 程序成果当前属于 `UrbanHeatOpt 测试版 V0.x`；只有完整供暖季、三模式、
  源—网—荷—储、成本—碳排、Pareto 和基本 QA 全部通过后才发布正式版 V1.0。
- 输入结构独立使用 `competition_input_3.0.0-draft.1`。字段稳定后只去掉
  `draft.1`，发布 `competition_input_3.0.0`；它不是程序 V3。
- 旧 `competition_input_v1/v2_1` 只用于显式历史回归，新入口不得自动迁移
  或回退。

## 本草案冻结的边界

三种供热模式必须共用建筑、负荷、时间、气象、价格、碳因子、设备参数、
可靠性和评价口径。内部统一使用 `kW_th/kWh_th`、`kW_e/kWh_e`、
`kWh_LHV`、`CNY/year` 和 `kgCO2e/year`。

契约新增并固定：

- 中央空气源热泵、中央燃气锅炉、分布式空气源热泵和水蓄热四类角色；
- 温度 COP 模块的逐时 `cop` 与 `capacity_ratio` 输出；
- 三档管径、每档容量、造价、线性热损和线性泵耗参数；
- 公共逐时时间权重、绝对电气价格、逐时电力和燃气碳因子；
- 成本—物理碳排 epsilon-constraint，V0 为 5 点、V1 为 11 点；
- 每次运行记录程序轨道、契约、参数版本、Git SHA 和输入文件哈希。
- 站点、接入和 HNS 罚值均为显式案例参数；缺失时阻止运行，不在代码中
  猜测或静默补零。

## 物理模块交付接口

候选站/管网模块只返回候选点与物理候选管段，不直接选择最终方案。COP 模块
在构模前生成逐时线性系数。储热模块提供容量、充放、损失和 SOC 约束。管损
和泵耗分别提供热损及购电表达，经济与碳排模块只消费这些标准输出。

`v0-smoke` 允许固定 COP、暂不启用管损和泵耗，但仍必须使用同一字段结构；
`v1-full` 强制温度 COP、容量修正、管损、泵耗、完整供暖季和零未供热政策。

## 尚未宣称完成的能力

本文件与机器 Schema 只冻结接口。目前尚未因此自动获得候选站生成、储热物理
约束、温度插值、管损、泵耗、Pareto 求解或完整供暖季结果；这些必须在后续
节点逐项实现并通过手算和端到端 QA。
