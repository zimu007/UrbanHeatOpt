# UrbanHeatOpt 正式版 V1.0 发布门

## 判定原则

V1.0 是第一版正式可用版本，不是 V0 合成案例的改名。只有以下项目全部通过，
才允许在结果中写 `UrbanHeatOpt-V1.0`：

1. 输入契约从 `competition_input_3.0.0-draft.N` 冻结为
   `competition_input_3.0.0`；
2. 三种模式使用同一 Canonical 数据和同一新 Pyomo Core；
3. 正式温度 COP/容量修正 Provider 已交付并验收；
4. 储热、线性管损和泵耗使用签认参数；
5. 候选站/道路候选管网模块已实现并联合验收；
6. 完整供暖季为 2160 个连续小时，每小时权重为 1；
7. 三种模式成本/碳端点及 11 点 Pareto 全部求解；
8. 未供热为 0，且热平衡、容量、连通、SOC、成本和碳排独立 QA 全通过；
9. 结果记录 Git SHA、全部输入哈希、参数版本和假设清单；
10. 相同输入、种子和求解器设置重复运行一致。

只读检查命令：

```powershell
python scripts/check_v1_release_gate.py --case <正式案例目录> --run-dir <正式结果目录>
```

退出码 0 表示全部通过，2 表示仍受阻。检查脚本不运行求解器、不修改输入或
结果，也不会把 V0 能力自动解释成 V1。

## 2026-08-21 当前阻塞

- 当前契约仍为 `competition_input_3.0.0-draft.2`；
- 当前程序轨道仍为 `UrbanHeatOpt-test-V0.x`；
- 正式温度 COP/容量修正 Provider 未交付；
- V0 管损、泵耗输入系数均为 0，不能代表工程计算；
- 自动候选站与道路候选管网算法未交付；
- 未接收 2160 小时正式负荷、能源价格、碳因子和专业签认参数；
- 尚未生成正式 11 点 Pareto 和完整季 QA。

因此当前交付只能称为 V0 合成闭环，不能称为 V1.0。
