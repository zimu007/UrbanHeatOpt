# 项目组待确认参数与关闭条件

本文只记录不能由代码组或负荷组自行猜测的正式项目参数。P0 合成案例使用的数值必须标记 `synthetic_test`，不得用于关闭下列问题。

| 编号 | 待确认事项 | 责任方 | 必需证据 | 关闭条件 |
|---|---|---|---|---|
| PJ-01 | 正式供水温度、回水温度及适用场景 | 供热系统专业负责人 | 设计条件、设备/末端适配说明和版本 | 两个温度以 `degC` 写入正式案例配置，满足供水高于回水，并完成专业负责人签认 |
| PJ-02 | 规划期、折现率、价格基年 | 项目经济负责人 | 项目统一经济评价口径及发布日期 | 三项形成可追溯书面口径；当前附件已批准 `CAPEX/lifetime` 简单年化，规划期和折现率只作追溯，不得用于 CRF、替换或残值 |
| PJ-03 | 设备容量、CAPEX、固定维护比例、可变运维、寿命 | 技术经济负责人 | 厂商、文献或项目询价表，含币种、税口径、价格基年和运维分母 | 每个启用技术均有完整 `technologies.csv` 行；固定维护明确为 `[0,1]` 无量纲年度比例，可变运维明确为 `CNY/kWh_th`；附件仅列维护系数字段名，未给数值，不得自行填入 |
| PJ-04 | 管网每米投资和寿命 | 管网与技术经济负责人 | 管径/敷设边界、投资来源、价格基年和资产寿命 | `network_economics.pipe_capex_CNY_per_m` 与 `pipe_lifetime_years` 经签认，适用范围与候选网络口径一致 |
| PJ-05 | 每个需求节点的接入投资和寿命 | 末端与技术经济负责人 | 接入工程边界、计价依据及是否含换热站/二次侧 | `connection_economics.by_demand_node` 完整覆盖需求节点，投资与寿命经签认且无重复计价 |
| PJ-06 | 正式道路、可建设空间、禁建和贴靠规则 | GIS/规划负责人 | 可授权 GIS 数据、CRS、发布日期和规则说明 | 标准空间文件通过校验，候选点/管网方法与数据能力匹配 |
| PJ-07 | 余热、污水、河湖等资源位置与可用量 | 资源专业负责人 | 资源位置、逐时 kW 可用量、技术关联和来源 | 资源数据完整且相应功能实现、测试并发布新契约版本；P0 v1 不可关闭为“已支持” |
| PJ-08 | 电价、气价、碳因子和能源边界 | 能源经济/碳核算负责人 | 分时规则、计价单位、LHV/HHV、体积基准状态和核算标准版本 | 外部时序与技术能源载体一一对应；附件只写 `3.54 CNY/m³`，只有体积价与 LHV 采用完全相同基准并有热值来源时，才允许在输入边界转换一次为 `CNY/kWh_LHV` |
| PJ-10 | HNS 罚值的正式取值与解释 | 项目经济与可靠性负责人 | 允许短缺边界、罚值依据、是否只用于求解及结果披露规则 | `reliability.hns_penalty_CNY_per_kWh` 经签认；结果同时报告真实成本和 HNS 罚项，不把罚项伪装成真实支出 |
| PJ-09 | 正式场景是否覆盖完整供暖季和完整 DHW 服务 | 项目技术负责人 | 场景定义、供暖季日历和 DHW 范围 | `complete_heating_season=true`、`dhw_included=true`，方可使用年度目标标签 |

所有关闭项必须记录责任人、确认日期、数据版本和来源文件 SHA-256。口头数值或合成测试结果不能作为关闭证据。
